## Vendor-described behavior (not tested here)

- Strands Box documents OS-level workload isolation plus policy checks for its shell, Python interpreter, egress gateway, and MCP broker. Its README says current support is macOS on Apple silicon, with Linux support planned; its getting-started guide names macOS 15+, Apple silicon, Node.js 22.21+, and a model credential as prerequisites. Direct filesystem grants are enforced by the OS and do not create individual policy decision records. See [Strands Box README](https://github.com/strands-agents/box) and its [security guide](https://github.com/strands-agents/box/blob/main/docs/user/security.md).
- OpenShell documents sandbox isolation with kernel-level file/system-call controls and policy-checked network connections. Its README lists Linux, macOS Apple silicon, and Windows WSL 2 (experimental), with Docker, Podman, or host virtualization; an install sets up a CLI and local gateway. See [OpenShell README](https://github.com/NVIDIA/OpenShell) and [installation guide](https://docs.nvidia.com/openshell/latest/about/installation/).

Those statements summarize vendor documentation only. They are not independently verified findings and must not be reported as Kineti test results.

## Reproducible comparison protocol

Run both candidates on the same dedicated disposable host or VM snapshot, with the same agent workload, repository fixture, explicit policies, and resource budget. Pin each runtime release and image by digest. Record host OS/build/architecture, runtime and CLI versions, configuration and policy digests, exact commands, exit codes, stdout/stderr, decision logs, and before/after fixture digests. Keep credentials out of the fixture and environment.

For every scenario below, execute the same workload once under each product. Mark each result `pass`, `fail`, or `unsupported`; attach inspectable logs and digests. `unsupported` is required where the platform, policy surface, or safe disposable-host setup cannot exercise the case.

| Scenario | Workload and expected observation |
|---|---|
| Declared filesystem boundary | Read/write a granted fixture path, then attempt read/write of a host sentinel outside the grant. Record file content digests and policy/OS decisions. |
| Host-path escape and symlink | Attempt `..`, absolute host paths, and a symlink that targets the outside sentinel. Confirm denied access and unchanged sentinel. |
| Process boundary | Attempt an unapproved executable and a privileged operation. Record process tree, exit code, and enforcement log. |
| Network policy | Attempt a denied loopback/host endpoint and a separately declared allowed endpoint. Record server-side request logs; no Internet endpoint is needed. |
| Credential non-disclosure | Put a synthetic high-entropy sentinel in the host credential source; attempt direct read and exfiltration to the local denied endpoint. Confirm no secret bytes appear in workload output or server logs. |
| Resource limits | Run bounded CPU, memory, and child-process probes. Record configured limits, observed peak use, termination status, and host health. |
| Crash and recovery | Terminate the agent/runtime during a write to disposable data, restart according to documented recovery, and verify host sentinel and runtime state. |

A product result is `pass` only when the expected denied or allowed behavior is independently visible in the evidence and the host sentinel checks agree. Missing logs, ambiguous policy configuration, or an unavailable probe are `unsupported`, never pass. Never run escape tests on a developer host with personal data or credentials.
