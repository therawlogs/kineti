## Shared workflow and trust rules

For new projects, use this order:

**Select harness, gate, or both → discovery → approve storyboard and mock-data shape → approve real-data intake or choose no-data path → refine features, architecture, tools, feasibility → approve outcome contract and priorities → build and verify.**

There is no default mode. Installing Kineti does not activate a project. Ordinary chat creates no project state. Bug fixes, review, and cleanup may enter at the relevant step.

Keep existing 13 stage identifiers readable. Add separate workflow-step and decision records rather than renumbering state. A legacy project stays readable with mode pending. Keep unknowns unknown. Tie approvals to artifact versions and reopen only decisions affected by changed inputs.

The owner-controlled evaluator/service owns the required-check inventory, policy, evaluator identity, signing authority, authoritative replay state, immutable evaluation input, and output destination. The builder cannot change these. Trusted checks execute outside candidate control and exercise the candidate through a declared isolated interface; candidate code is not imported into an unrestricted trusted observer. Candidate test output, model assurances, filenames, and case counts cannot authorize a write.

Introduce a versioned authenticated evaluation/check-manifest format. Preserve existing local receipts at their current assurance level; do not silently upgrade them. Bind raw required bytes, command arguments, runner/parser/toolchain, declared dependency scope, environment hashes, artifact, and check inventory. A lockfile alone does not establish installed dependency bytes. Missing or unverifiable required inputs deny trusted acceptance. Do not log secret values. Distinguish test execution from typecheck and packaging success.

Local protocol coverage is implemented in `src/security/evaluation-contract.ts`: an owner-signed inventory and a separately evaluator-signed result must match out-of-band artifact, contract, policy, inventory, key, and runner pins. This validates the protocol shape only; it does not execute checks independently, establish service custody, or upgrade local receipts.

Protected-output requests bind the evaluated artifact, approved operation, service-owned destination, exact bytes, policy, and unique request. Outcomes distinguish denied, pending, applied, and unknown. Reconcile interrupted effects before retry. Missing or damaged initialized replay state requires owner recovery. Do not claim distributed exactly-once behavior.
