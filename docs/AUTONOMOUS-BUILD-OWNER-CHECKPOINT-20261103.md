# Owner-service implementation checkpoint

Date: 2026-11-03. Local implementation and offline evidence only. The owner service is not complete and no A01–A14 row is accepted by this checkpoint. No release action was performed.

## Completed implementation

The grant, durable audit, repair and recovery engine now uses a platform boundary in `task_backend.rs`. The admitted Linux backend retains the separate owner UID, cgroup memory/process controls, kernel peer identity and crash supervisor. The engine compiles on macOS, but macOS admission deliberately denies execution until its VM/worker/storage/resource requirements are connected. Compiling that branch is not macOS task-service acceptance.

`kineti task inspect --owner-store ... --id ...` now reads protected owner evidence without starting a service or minting task authority. It checks the audit chain and grant/approval binding and reports whether the inspecting executable matches the approved one. It does not repair records, reset counters, resume interrupted work or expose an additional agent MCP tool. Reopening an interrupted service fences it and directs the owner to inspect; no task action is replayed. Prior approval, work and interrupted execution records remain intact.

The copied-workspace checkpoint codec rejects excluded/traversing paths, redirected parents, special objects, hard-linked source files, extra data, invalid digests, special permission bits and oversized transfers. It creates only new destinations and preserves bytes, supported modes and internal relative links. Its 16 MB transfer class is an implementation limit, not an operating-system disk quota. Encoding a changing directory is not an atomic checkpoint; macOS still needs a sealed read-only guest projection before this can be used as its runtime boundary.

A separate macOS `host vm-revoke` now takes the same exclusive lease as VM startup before acknowledging stop. It refuses while an active owner holds the lease. The active controller must close its private `host vm-run` lifetime channel and join that process: the native controller kills and reaps its owned foreground launcher before confirming stopped state. This closes the false-acknowledgment race during startup; it does not turn a process group or a PID file into a descendant boundary.
