AI-PR verification & anti-tampering gate.

Everything you need to lock test policy on your protected base branch, block AI PR test tampering with kineti pr-check, verify polyglot test runs under kineti test run, wire action.yml on Linux GitHub Actions, and archive Ed25519-signed kineti-pr-audit-v1 bundles.

1. Install & repository initialization (kineti init)

Kineti 1.0.1 ships as a single offline MIT-licensed Rust executable (kineti) targeting Linux CI runners (x86_64 and aarch64) and macOS/Linux POSIX workstations. It requires zero outbound network calls and neither Node.js nor Bun at runtime.

Build from source (works today) 
cargo build --release --locked --manifest-path core-native/Cargo.toml
./core-native/target/release/kineti --version

# Run the self-contained 4-scene offline demo (zero network, cleans up on exit)
./examples/pilot-demo/run-demo.sh
Cargo & npm 1.0.1 publication status: 1.0.1 is currently an open-core release candidate. Registry commands (cargo install kineti-cli --version '=1.0.1' --locked and npm install -g kineti@1.0.1) activate after multi-platform archive acceptance and separate release approval. Historical 0.6.1 packages are retired (yanked on crates.io, deprecated on npm).

Preview repository initialization with an explicit project goal before applying (Kineti never invents a goal or overwrites an existing locked goal):

Initialize local state and starter gate.json 
kineti init --goal "Enforce verified AI pull requests"
kineti init --goal "Enforce verified AI pull requests" --apply

kineti init --apply writes local .kineti/state.json (keep runtime state excluded from Git) and creates starter .kineti/gate.json with an explicit "commands": {} map. Commit only .kineti/gate.json to your protected base branch.

2. Base-branch .kineti/gate.json policy

Commit .kineti/gate.json to your protected base branch (for example, main). During pull-request verification, kineti pr-check loads policy strictly from git show <base-ref>:.kineti/gate.json—never trusting edits inside the PR branch.

.kineti/gate.json 
{
  "version": 1,
  "required_checks": ["unit"],
  "commands": {
    "unit": ["pytest", "-q", "tests/"]
  },
  "parsers": {
    "unit": "exit-code"
  },
  "min_passed": {
    "rust-unit": 25
  },
  "required_tests": [
    "tests/test_auth.py",
    "tests/billing.test.js",
    "tests/core_test.rs"
  ],
  "protected_paths": [
    ".kineti/gate.json",
    ".github/workflows/",
    "pytest.ini",
    "jest.config.ts"
  ],
  "max_deleted_tests": 0,
  "max_age_minutes": 240,
  "exclude": [".pytest_cache", "__pycache__"]
}
  • required_checks: Labels that kineti ci and action.yml must verify before passing.
  • commands: Exact shell-free argv arrays keyed by label. kineti ci fails closed (exit 1) whenever a required label lacks a declared command mapping (unless explicitly passed via --evidence-commands).
  • parsers: Optional per-label parser mode ("auto", "cargo", "bun", or "exit-code").
  • min_passed: Optional minimum observed passing count (either a positive integer or per-label map) for count-aware runners.
  • required_tests: Test files or directories that must exist and cannot be deleted or renamed away in a PR.
  • protected_paths: Files and directory prefixes guarded against unauthorized PR modification.
  • max_deleted_tests: Maximum net test-function deletions permitted before blocking (default 0).
  • exclude: Additional Tier 2 (non-Git) walker exclusions when git is unavailable.

3. Supervised tests & two-tier freshness (kineti test)

Run exact allowlisted commands under Kineti’s POSIX process-group supervisor and capture Ed25519-signed receipts:

Run & verify supervised test receipts 
# Count-aware parser (cargo test or multi-suite bun test)
kineti test run --label rust-unit --required-test tests/ --parser auto -- cargo test

# Allowlisted polyglot parser (pytest, jest, vitest, go test, node --test, make test)
kineti test run --label unit --required-test tests/test_auth.py --parser exit-code -- pytest -q tests/

# Verify freshness, exact argv, required test presence, and signature
kineti test check --label unit

Two-tier parser contract

ModeSupported RunnersVerification Behavior
--parser auto cargo test, bun test Built-in count-aware parsing. Sums all test-result suites across stdout+stderr (including multi-suite bun test), requires passed > 0, failed == 0, and skipped == 0 unless --allow-ignored is explicitly passed. Supports optional min_passed floors.
--parser exit-code Any allowlisted command (pytest, jest, vitest, go test, node --test, make test) Enforces exit status 0, exact argv, required test path presence, untruncated capture, non-mutated workspace tree, and POSIX timeout cleanup. Explicitly records "parser": "kineti-exit-code-v1" and "count_observed": false.

Two-tier streaming O_NOFOLLOW freshness

  • Tier 1 (Git worktree + git on PATH): Enumerates tracked and non-ignored files with git -c core.excludesFile=/dev/null ls-files -z --cached --others --exclude-standard, stream-hashes in 64 KiB chunks with O_NOFOLLOW, filters deleted tracked entries, and explicitly hashes root and nested .gitignore files plus .git/info/exclude.
  • Tier 2 (Non-Git directory or git absent): Bounded pure-Rust O_NOFOLLOW walker respecting .kineti/gate.json exclude rules and safe cache defaults (.git, .kineti, .pytest_cache, __pycache__, node_modules)—with zero silent depth-agnostic bypass of directories named legacy, build, dist, or target.
  • Constant-size evidence log: Each line in .kineti/evidence.jsonl stores constant-size inventory_sha256 and inventory_count digests while remaining backwards-compatible with reading historical v3 lines. Any 1-byte source edit invalidates freshness and causes kineti test check to exit 4.

4. Pull-request anti-tampering (kineti pr-check)

Inspect a pull request diff against protected base-branch policy, validate required receipts, and emit signed compliance outputs:

kineti pr-check command 
kineti pr-check \
  --base-ref main \
  --head-ref HEAD \
  --require-ci \
  --require-evidence unit \
  --audit-out .kineti/pr-audit.json \
  --summary-out .kineti/pr-summary.md
  • Base-branch policy integrity: Fails closed (exit 1, policy_tamper_detected) if the PR modifies or deletes .kineti/gate.json, .github/workflows/**, or configured protected_paths—unless CI explicitly passes --allow-policy-change (for example, after CODEOWNER review).
  • Polyglot test-tampering diff scanner: Scans shell-free git diff --unified=0 --no-color <base>...<head> (hardened against diff.noprefix=true, inline/multi-line block-comment smuggling, and spaced filenames) and returns structured {file, line, rule, snippet} findings (exit 1) for:
    • Deletion or rename-removal of base-branch required_tests.
    • Newly added skip, ignore, focus, or xfail markers: Rust (#[ignore], #[ ignore ], #[core::prelude::v1::ignore]), Python (@pytest.mark.skip, @pytest.mark.skipif, @pytest.mark.xfail, @unittest.skip, pytest.skip(), JS/TS (test.skip(, it.skip(, describe.skip(, test.only(, it.only(, describe.only(, test.todo(, it.todo(), Go (t.Skip(, t.Skipf(, t.SkipNow().
    • Net deletion of test definitions (#[test], def test_, func Test, test(, it() exceeding max_deleted_tests unless --allow-test-reduction is explicitly passed.
    • Weakening flags added to CI workflows or package.json test scripts (--passWithNoTests, -k "", --ignore, or no-op test scripts).
  • CI & evidence linkage: --require-evidence <label> validates receipts strictly against the base-branch policy; --require-ci ensures spend/stage consistency before marking an audit bundle passed.

5. Participating CI & GitHub Action (kineti ci & action.yml)

Run kineti ci directly in any POSIX CI pipeline, or wire Kineti’s composite Linux GitHub Action with read-only permissions:

.github/workflows/kineti-pr-gate.yml 
name: Kineti AI-PR Gate
on:
  pull_request:
    branches: [main]

permissions:
  contents: read

jobs:
  verify:
    runs-on: ubuntu-24.04
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0
      - name: Run Kineti PR Gate
        uses: ./
        with:
          executable: /usr/local/bin/kineti
          base-ref: ${{ github.event.pull_request.base.sha }}
          head-ref: ${{ github.event.pull_request.head.sha }}
          allow-policy-change: "false"
          allow-test-reduction: "false"
          audit-out: .kineti/pr-audit.json
          summary-out: .kineti/pr-summary.md
          write-step-summary: "true"

In order, action.yml runs a preflight kineti pr-check against the protected base-branch .kineti/gate.json to fail fast before executing untrusted PR test code; extracts base-branch required_checks, commands, parsers, min_passed, and required_tests; runs supervised kineti test run for each required label; enforces kineti ci; and writes the final Ed25519-signed kineti-pr-audit-v1 bundle plus Markdown summary to $GITHUB_STEP_SUMMARY.

8. Reported spending, CLI-only undo & local MCP

  • Reported spending (kineti spend check): Uses integer monetary units, total/stage ceilings, and a 95% stop. Corruption, unresolved reservations, and unknown historical costs fail closed (exit 3). Reported spending is operator-recorded accounting, not provider-bill verification.
  • Registered undo (kineti undo push / rollback): Strictly CLI-only (removed from MCP to prevent stored command injection). Runs newest-first with durable intent/completion records and blocks uncertain replay after interruption until explicit inspection.
  • Local MCP (kineti mcp): Speaks stdin/stdout JSON-RPC with no HTTP listener and exposes 6 tools. kineti_evidence_record strictly enforces exact allowlisted label and argv entries from .kineti/gate.json. Local MCP has previously been tested only on macOS arm64 with specific Codex versions; Cursor and Antigravity remain unverified.

9. Honest limits & Open-Core Pilot

  • CI vs. local boundary: A protected CI runner reading base-branch .kineti/gate.json is the enforcement boundary. Local same-account checks cannot stop an agent with local write access from modifying files outside Kineti.
  • Signatures are not assertion quality: Ed25519 signatures prove record integrity relative to the signing key—never that tests contain meaningful assertions or did not fabricate output ("independent_assertion_quality_proven": false).
  • Parser transparency: Count-aware verification applies to cargo test and multi-suite bun test; --parser exit-code runners explicitly set "count_observed": false.
  • No hidden interception: No automatic command interception, no kernel sandboxing, no protected writes, no atomic authorization of later writes, and no automatic redaction of credentials placed inside command arguments.
  • Confirmation flags: Interactive confirmation flags record acknowledgment; they do not establish human identity.
