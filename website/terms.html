2. Self-Hosted Offline Execution & Verification Scope

Organizations run Kineti offline on their own Linux CI runners (such as GitHub Actions) or local machines. Kineti does not operate a hosted runner, SaaS evaluation service, or uptime-backed cloud platform. Each organization controls its own CI infrastructure, branch protection rules, and artifact storage.

Kineti checks participating workflows against base-branch .kineti/gate.json policy, scans PR diffs for configured policy and test tampering, verifies recorded inputs, and signs kineti-pr-audit-v1 bundles. Kineti does not provide automatic command interception, kernel sandboxing, protected writes, atomic authorization of later writes, or provider-bill verification.

3. Signatures, Parsers & Host Limits

  • Cryptographic signatures on receipts and kineti-pr-audit-v1 bundles prove record integrity relative to the signing key; they do not prove test assertion quality (independent_assertion_quality_proven: false).
  • Built-in count-aware test parsing covers cargo test and multi-suite bun test. Allowlisted polyglot runners executed with --parser exit-code explicitly record count_observed: false.
  • Native MCP integration has previously been tested only on specific macOS arm64 Codex versions; Cursor and Antigravity remain unverified.

4. Third-Party Services & Local Artifacts

GitHub Actions, Git hosting platforms, coding agents, and model providers remain governed by their own terms and privacy policies. Runtime state under .kineti/ and generated audit bundles reside strictly on your runners or machines; uninstalling Kineti removes only Kineti-owned integration files while leaving your repository history and backups intact. Do not commit runtime state or credentials to Git.
