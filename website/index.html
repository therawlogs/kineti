Open-Core AI-PR Verification Gate

Keep AI pull requests honest before they merge.

Standard CI runs whatever tests and workflow files sit on the PR branch—so an AI coding agent can turn a red build green by skipping tests, deleting assertions, or weakening CI rules. Kineti locks test policy to your protected base branch, catches PR-diff test tampering across Rust, Python, JS/TS, and Go, and signs verifiable audit packs right on your Linux runner.

An AI PR weakens .kineti/gate.json so required tests stop running. Kineti loads policy strictly from main and blocks immediately.

--- a/.kineti/gate.json (protected main)
+++ b/.kineti/gate.json (pull request)
-  "required_checks": ["unit"],
-  "commands": { "unit": ["pytest", "-q", "tests/"] }
+  "required_checks": [],
+  "commands": { "unit": ["/bin/true"] }
$ kineti pr-check --base-ref main --head-ref HEAD
BLOCKED (exit 1) policy_tamper_detected=true
  protected_path: .kineti/gate.json
  base_policy:    loaded from git show main:.kineti/gate.json
  override:       requires explicit --allow-policy-change from CI

Why Teams Use Kineti

What happens when AI agents write pull requests at scale.

Reviewers can’t manually inspect every line of an 800-line AI PR looking for a hidden it.skip, deleted assertion, or edited CI config. Kineti makes those shortcuts impossible to merge silently.

01 · BASE-BRANCH LOCK

The PR cannot rewrite its own rules

kineti pr-check loads .kineti/gate.json strictly from your protected base commit. Any unauthorized PR change to gate rules, .github/workflows/**, or protected test configs fails closed with exit 1.

02 · POLYGLOT DIFF SCANNER

Catches skipped & deleted tests automatically

Deterministically scans diffs across Rust, Python, JavaScript/TypeScript, and Go for deleted required test files, net test deletions, skip/ignore/only/xfail markers, and weakening flags like --passWithNoTests.

03 · OFFLINE & AUDIT-READY

Zero telemetry, signed change-control proof

One ~2.4 MB Rust binary runs completely offline inside your own Linux GitHub Actions runner (permissions: contents: read) and emits Ed25519-signed kineti-pr-audit-v1 JSON + Markdown Step Summaries.

How It Works

Four checks on every pull request.

Drop Kineti’s composite GitHub Action into your pull-request workflow. If a PR tampers with policy or tests, Kineti blocks immediately before untrusted PR test code even runs.

Supported stacks & parser transparency

Count-aware (--parser auto) cargo test · multi-suite bun test
Polyglot (--parser exit-code) pytest · jest · vitest · go test · node --test · make test
Diff anti-tamper languages Rust · Python · JS / TS · Go · CI & package.json
Runtime requirements Linux / macOS POSIX · zero Node/Bun · zero network
  1. 01

    Preflight base-branch policy & diff check

    Reads .kineti/gate.json from git show <base-sha>:.kineti/gate.json and scans the PR diff for policy edits, deleted required test files, added skip/ignore markers, or net test deletions. Fails closed before running PR code.

  2. 02

    Supervised allowlisted test execution

    Runs only the exact shell-free argv commands declared on the base branch under a POSIX process-group deadline with streaming O_NOFOLLOW workspace hashing—detecting even 1-byte edits anywhere in the tree.

  3. 03

    Fail-closed CI & receipt verification

    kineti ci verifies every required label has a fresh, untampered receipt matching exact argv, parser rules, and optional min_passed floors—blocking spoofed or stale evidence.

  4. 04

    Signed kineti-pr-audit-v1 & Step Summary

    Writes a canonical Ed25519-signed JSON compliance bundle and a clean Markdown table to $GITHUB_STEP_SUMMARY with exact SHAs, base policy digest, executed commands, findings, and explicit honesty flags.

Install & Quickstart · v1.0.1

Try Kineti 1.0 in minutes.

The entire CLI, GitHub Action, and 4-scene offline demo are open-core under the MIT License. Choose how you want to run it today.

Commit .kineti/gate.json on your protected main branch, then add this read-only pull-request workflow to your repository:

.github/workflows/kineti-pr-gate.yml 
name: Kineti PR Gate
on:
  pull_request:
    branches: [main]

permissions:
  contents: read

jobs:
  verify:
    runs-on: ubuntu-24.04
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0
      - name: Run Kineti PR Gate
        uses: therawlogs/kineti@v1
        with:
          base-ref: ${{ github.event.pull_request.base.sha }}
          head-ref: ${{ github.event.pull_request.head.sha }}
          audit-out: .kineti/pr-audit.json
          summary-out: .kineti/pr-summary.md
          write-step-summary: "true"

See the full .kineti/gate.json schema and action.yml reference →

Build the ~2.4 MB stripped native binary with Rust/Cargo (runtime needs neither Node.js nor Bun), then run the 15-second offline 4-scene demo:

Build & run 4-scene offline demo 
# 1. Build native binary (Linux or macOS)
cargo build --release --locked --manifest-path core-native/Cargo.toml
./core-native/target/release/kineti --version

# 2. Run all 4 live anti-tamper & audit scenes offline (cleans up automatically)
./examples/pilot-demo/run-demo.sh

# 3. Preview & apply initialization in a repository
kineti init --goal "Ship verified pull requests"
kineti init --goal "Ship verified pull requests" --apply

What Kineti explicitly does — and does not — guarantee

Signatures prove integrity, not assertion quality

Ed25519 signatures bind exact commits, base policy digests, commands, and workspace hashes. They do not prove that test assertions are meaningful—every audit pack explicitly sets "independent_assertion_quality_proven": false.

Count-aware vs. exit-code parsers

--parser auto checks observed pass/fail/skip counts for cargo test and multi-suite bun test. Polyglot runners via --parser exit-code verify exit 0, exact argv, required tests, and freshness while explicitly recording "count_observed": false.

Protected CI runner is the real trust boundary

Kineti is not a laptop VM, container, or kernel sandbox. Local checks catch accidental staleness, while tamper-resistant enforcement comes from running on a protected CI runner reading base-branch .kineti/gate.json.

No hidden hooks, unverified hosts & argv secrets

No automatic local command interception, no protected writes, and no provider-bill verification. Local MCP allows only .kineti/gate.json commands (undo is CLI-only); Cursor and Antigravity remain unverified. Never pass secrets inside command argv.
