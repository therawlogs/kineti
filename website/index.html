What It Catches

Three shortcuts AI agents take on red PRs.

01 · POLICY TAMPER

Rewriting CI or gate rules

Reads .kineti/gate.json strictly from main and blocks PR edits to workflows or test configs.

.github/workflows/* exit 1
02 · TEST TAMPERING

Skipping or deleting tests

Scans Rust, Python, JS/TS, and Go diffs for skip markers, deleted tests, and flags like --passWithNoTests.

@pytest.mark.skip · it.skip · #[ignore] exit 1
03 · STALE RECEIPTS

Editing code after tests pass

Streaming O_NOFOLLOW workspace hashing invalidates receipts on even a 1-byte post-test edit.

inventory_sha256 mismatch exit 4

Verification Pipeline

Four checks on every pull request.

Tamper checks fail closed before untrusted PR test commands ever execute. Read full reference →

1 preflight

Lock base policy

Loads .kineti/gate.json from main and scans the PR diff for tampering.

2 supervised

Run allowlisted tests

Executes exact main commands under a POSIX deadline and hashes the tree.

3 fail-closed

Verify receipts

kineti ci checks every required label for fresh, untampered evidence.

4 Ed25519

Sign audit bundle

Outputs kineti-pr-audit-v1 JSON and a Markdown GitHub Step Summary.

Stacks: Rust (cargo test) Python (pytest) JS / TS (bun · jest · vitest) Go (go test) JUnit XML (--parser junit) Linux & macOS (x64 · arm64) Zero Node/Bun at runtime

Install & Quickstart · v1.0.1

Try Kineti 1.0 in minutes.

Commit .kineti/gate.json on main, then add this read-only workflow (policy schema →):

.github/workflows/kineti-pr-gate.yml 
name: Kineti PR Gate
on:
  pull_request:
    branches: [main]

permissions:
  contents: read

jobs:
  verify:
    runs-on: ubuntu-24.04
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0
      - name: Run Kineti PR Gate
        uses: therawlogs/kineti@v1
        with:
          base-ref: ${{ github.event.pull_request.base.sha }}
          head-ref: ${{ github.event.pull_request.head.sha }}
          audit-out: .kineti/pr-audit.json
          summary-out: .kineti/pr-summary.md
          write-step-summary: "true"

Honest scope: what Kineti guarantees — and what it doesn’t

Signatures prove integrity, not assertion quality

Ed25519 signatures bind exact commits, base policy digests, commands, and workspace hashes. Every audit pack sets "independent_assertion_quality_proven": false.

Count-aware vs. exit-code parsers

--parser auto checks counts for cargo test, bun test, and JUnit XML (--parser junit). --parser exit-code verifies exit 0 and freshness while recording "count_observed": false.

Protected CI runner is the trust boundary

Kineti is not a kernel sandbox. Tamper-resistant enforcement comes from running on a protected CI runner reading base-branch .kineti/gate.json.

No hidden hooks, unverified hosts & argv secrets

No automatic command interception, protected writes, or provider-bill verification. Cursor and Antigravity remain unverified; never pass secrets in argv.
